# VPN 訂閱系統

商用網路客戶端的工程專案，包含帳號、付款與續費。我參與產品流程、Swift／SwiftUI 客戶端、Node.js 服務、付款狀態與交接。

使用者付款後，回到客戶端應該看到正確的訂閱狀態。少付、晚到和服務重啟，讓這件事比畫面看起來複雜。

## 帳本保持精確，下一步讓人看得懂

每張訂單有自己的收款目的地，帳本保留實際收到的款項，包括少付和多付。介面說清楚下一步，不為了簡化顯示而改掉財務紀錄。

確認款項已經更新訂閱後，重複查帳或重新啟動都不能再加一次期限。到期前續費也要保留原本剩餘的時間。

## 已存在的訂單仍然要核款

地址額度用完可以停止新訂單，既有訂單卻還要繼續查帳。我把這兩種狀態分開，避免容量改變時，連已經開啟的付款頁都被一起藏起來。

晚到或狀態不明的款項保留人工處理路徑，不直接配給其他訂單，也不擅自當成另一筆續費。

## 交付狀態

工程交接包含受控後端與付款流程檢查、iOS 模擬器操作，以及未簽署的裝置目標編譯。正式基礎設施、真實款項、簽署與目標網路驗收，另外列於[驗證筆記](docs/verification.md)。

較早的瀏覽器客戶端僅處理瀏覽器連線，和這裡描述的原生版本有不同範圍。
