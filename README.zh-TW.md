## 要解決什麼

使用者需要選擇連線地區、看懂方案、完成付款，再回到客戶端取得正確的使用資格。真正容易出錯的是畫面之間的狀態：少付、晚付、到期前續費，或查帳途中服務重新啟動。

## 我的工作

參與產品範圍與操作流程、客戶端、訂閱付款狀態、異常處理及工程交接。實作包含 Swift／SwiftUI iOS 客戶端、Node.js 服務與瀏覽器付款頁。較早的瀏覽器版本只處理瀏覽器可代理的連線，兩者能力範圍分開描述。

## 關鍵取捨

每張訂單使用獨立的收款目的地，讓款項歸屬有依據。介面讓人看懂下一步該付什麼，帳本仍保留實際收款精度。重複查帳或重新啟動後，同一筆確認款項只能開通一次。

新的訂單額度用完，不應阻斷已存在訂單的核款。過期或狀態不明的付款保留人工處理路徑；續費則保留原本未用完的時間。
